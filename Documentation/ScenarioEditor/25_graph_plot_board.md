# 25. ノードベース・プロットボード

作成日: 2026-05-15

## 位置づけ

グラフ機能を、相関図やシーン遷移の可視化だけでなく、プロットと脚本メモを作るための作業面として使う。

現状の `Plot Flow Lens` は、既存のチャプター / シーン / choice から「脚本の遷移」を読む機能である。一方、この資料で扱う `プロットボード` は、まだシーン化されていない筋、伏線、未解決の問い、キャラ別の進行、フレーバー案をノードとして置き、あとから章・シーン・脚本へ接続していく編集機能である。

## 解決したいこと

物語は単線ではなく、複数の流れが同時に進む。

- 主筋、サブプロット、キャラアーク、謎、伏線、感情線が別々の速度で進む。
- 1 つのシーンが複数のプロットを同時に進める。
- 脚本化前のメモは、章やシーンの中だけに置くと埋もれる。
- グラフ上で見えている関係性を、そのまま執筆メモや構成メモにしたい。

そのため、シーン一覧とは別に、ノードベースで「物語の進行単位」を扱う。

## 用語

| 用語 | 意味 |
|---|---|
| プロットボード | 複数のプロットノードと接続線を持つ編集キャンバス |
| プロットスレッド | 主筋、キャラ別の筋、謎、伏線など、同時進行する流れ |
| プロットノード | 出来事、転機、問い、伏線、脚本メモなどのカード |
| アンカー | プロットノードをチャプター、シーン、キャラ、場所、用語、脚本ブロックへ紐づける参照 |
| 実現先 | プロットノードが実際に書かれたシーン、またはこれから書く予定のシーン |

## 既存機能との違い

| 機能 | 主な役割 | データの向き |
|---|---|---|
| Relationship Lens | キャラ、場所、用語などの関係を見る / 編集する | ノードとリレーションが一次データ |
| Plot Flow Lens | 既存シーンの遷移と分岐を読む | 脚本 YAML から派生 |
| Graph Comments | グラフ上の自由メモ | 注釈。意味構造は持たない |
| プロットボード | 物語の並行する筋と脚本メモを作る | プロットボード自体が一次データ |

`Graph Comments` を拡張するだけだと、シーンやキャラへの参照、エクスポート、AI への文脈渡し、共同編集時の差分管理が弱い。プロットボードは独立した保存対象にする。

## ノード種別

初期実装では、型を増やしすぎず以下に絞る。

| 種別 | 用途 |
|---|---|
| `thread` | 主筋、サブプロット、キャラアーク、謎、伏線などの流れ |
| `beat` | 出来事、転機、発覚、選択、対立、感情の変化 |
| `memo` | 脚本メモ、台詞案、演出案、未整理の断片 |
| `question` | 未解決の問い、要検討、矛盾確認 |
| `scene_ref` | 既存シーンまたは作成予定シーンへの参照 |

最初は `thread` と `beat` と `memo` だけでもよい。`question` と `scene_ref` は UI 上の区別として後から足せる。

## 接続線の種別

| 種別 | 意味 |
|---|---|
| `next` | 次に起きる / 次に扱う |
| `causes` | 原因になる |
| `foreshadows` | 伏線になる |
| `resolves` | 回収する |
| `blocks` | 進行を止める障害 |
| `contrasts` | 対比する |
| `belongs_to` | スレッドに属する |
| `realized_in` | シーンで実現される |

接続線は有向を基本にする。相互的な意味が必要な場合は、既存の関係性機能と同じく逆向きの線を別に持つ。

## 並行プロットの表現

プロットスレッドを「レーン」として扱い、同じボード内に複数の流れを並べる。

- `thread` ノードはレーンの見出しとして表示できる。
- `beat` は 1 つ以上の `thread` に属せる。
- 1 つの `beat` が複数スレッドを進める場合は、複数の `belongs_to` または `threadIds` を持つ。
- シーン順とは別に、グラフ上の位置で「同時進行」「対比」「遅れて回収」を表せる。
- 時系列が必要な場合は、後から Timeline / Era と連携する。

重要なのは、プロットボードをシーン順の別表現にしないこと。シーン順は `Plot Flow Lens`、並行する意味の流れは `プロットボード` が担当する。

## 保存形式案

まずはボード単位の YAML を `PlotBoards/` に置く。

```yaml
schemaVersion: 1
id: plotboard.main
title: 本編プロットボード
nodes:
  - id: pnode.thread.main
    kind: thread
    title: 主筋
    body: 王都崩壊から再起まで。
    position: { x: 0, y: 0 }
    color: "#dbeafe"

  - id: pnode.beat.false_victory
    kind: beat
    title: 偽りの勝利
    body: 勝ったように見えるが、敵の目的は別にある。
    threadIds:
      - pnode.thread.main
      - pnode.thread.mystery
    anchors:
      chapters:
        - ch_001
      scenes:
        - sc_003
      nodes:
        - node.aria
    status: draft
    position: { x: 280, y: 40 }

edges:
  - id: pedge.001
    source: pnode.beat.false_victory
    target: pnode.beat.truth_leak
    type: foreshadows
    label: 違和感を残す
```

### 保存方針

- プロットボードは `Scenarios/` とは分ける。
- 参照には表示名ではなく安定 ID を使う。
- 大規模化したら `PlotBoards/main/nodes/*.yaml` に分割できる余地を残す。
- 位置はこのボードにおいて意味を持つため、`position` をボード内に持たせてよい。
- Relationship / Plot Flow のノード位置とは別扱いにする。

## 脚本との接続

プロットノードは、最初から脚本本文に混ぜない。代わりにアンカーでつなぐ。

初期段階:

- チャプターへのリンク
- シーンへのリンク
- キャラ / 場所 / 用語ノードへのリンク
- ダブルクリックで該当シーンを脚本タブで開く
- シーン詳細に「関連プロットノード」を表示する

次段階:

- 脚本ブロックに安定 ID を付け、台詞やト書き単位へリンクする
- 脚本行の右クリックから「この行をプロットノードに接続」を追加する
- プロットノード側から「このメモを脚本へ挿入」を実行する

脚本ブロック単位のリンクは、現在の行番号や配列 index に頼ると壊れやすい。必要になった段階で `blockId` を導入する。

## UI 案

GraphPanel に Lens を追加する。

| Lens | 役割 |
|---|---|
| 関係性 | 既存ノードの相関図 |
| Plot Flow | 既存シーンの遷移図 |
| プロットボード | 並行プロットと脚本メモの編集 |

プロットボード Lens では以下を置く。

- 上部にボード選択、追加、リネーム、検索
- 左上または右クリックで `thread` / `beat` / `memo` 追加
- ノード内でタイトルと本文を直接編集
- ノードをドラッグして位置保存
- ノード同士をドラッグ接続して線種を選択
- ノード詳細にアンカー欄を持ち、シーン / キャラ / 場所を検索して紐づける
- シーンアンカーのクリックで ScriptPanel へジャンプ

カードは大きめにし、本文の数行が読めるようにする。現在の丸ノード表示だけでは脚本メモとして情報量が足りないため、`LensCanvas` は「丸ノード」と「カードノード」を描き分けられるように拡張する。

## AI / 外部用途との接続

プロットボードは、AI やレビュー用出力に渡す文脈として有効に使える。

- 選択中のスレッドだけを AI に渡して矛盾や不足を確認する。
- 関連シーンと一緒にプロットノードを prompt package 化する。
- Review HTML に「この章で進むプロットスレッド」を表示する。
- ゲーム実装向けには、プロットボードは基本的に出力対象外とし、必要な場合だけデバッグ資料として出す。

## 実装段階案

### 段階 1: 保存できるプロットボード

- `core` に `PlotBoard` / `PlotNode` / `PlotEdge` 型と parser / serializer を追加する。
- `PlotBoards/main.board.yaml` を読み書きする repository を追加する。
- `ProjectService` でプロットボードをロードし、保存対象に含める。
- GraphPanel に `プロットボード` Lens を追加する。
- ノード追加、移動、タイトル / 本文編集、削除を保存できるようにする。

### 段階 2: シーン / 要素へのアンカー

- プロットノードからチャプター、シーン、キャラ、場所、用語へリンクする。
- ダブルクリックやアンカークリックで該当タブを開く。
- シーン詳細に関連プロットノードを表示する。
- Project Health で参照切れを検出する。

### 段階 3: 並行プロット UX

- スレッド別の色、レーン表示、フィルタを追加する。
- 1 つの `beat` が複数スレッドに属する表示を整える。
- ボード内検索と「未解決 question 一覧」を追加する。
- Plot Flow Lens と並べて、実際のシーン順とプロット上の意味の流れを比較できるようにする。

### 段階 4: 脚本ブロック連携

- 脚本ブロックに安定 `blockId` を導入する。
- 脚本行からプロットノード作成 / 接続できるようにする。
- プロットメモを脚本ブロックへ変換する操作を追加する。

## 受け入れ基準

- プロットボード上で作ったノードと線が、プロジェクトを閉じても復元される。
- 1 つのシーンが複数プロットスレッドに紐づけられる。
- プロットノードから該当シーン、キャラ、場所へジャンプできる。
- シーンの並び順を変えても、プロットボードの意味構造は壊れない。
- 保存形式が Git diff で読める。
- プロットボードを使わない既存プロジェクトは、挙動が変わらない。

## 近い実装候補

最初の PR としては、以下の範囲に切るのがよい。

1. `PlotBoard` 型と YAML roundtrip test を追加する。
2. `PlotBoards/main.board.yaml` を保存する repository を追加する。
3. GraphPanel に `プロットボード` Lens を追加し、カードノードを表示する。
4. ノード追加 / 移動 / 本文編集 / 削除を保存する。
5. シーンリンクは `anchors.scenes` の保存だけに留め、ジャンプ UI は次 PR に分ける。
