# Scenario Studio はじめの一歩 — 環境構築 & プロジェクト立ち上げ手順書

完全に初めての人が、**環境構築から実際にプロジェクトを開いて書き始める**までを最短で辿るための手順書です。

到達点は 2 通り。どちらに進んでも OK です:

- **ルート A** — 真っ新な状態から、自分の作品を **ゼロから** 作る
- **ルート B** — すでにある企画書・プロット・キャラ設定・台本テキストなどを、**AI でまとめて ScenarioStudio 形式に再構築** する

> この文書は「手順」に特化しています。各機能の詳細・ショートカット・パネルの使い方は
> [`Documentation/UserGuide.md`](./UserGuide.md) を、ファイル形式の厳密な仕様は同 **§8（AI 向けデータ作成スペック）** を参照してください。
> 設計思想は [`Documentation/ScenarioEditor/00_README.md`](./ScenarioEditor/00_README.md)。

---

## 0. 環境構築（A / B 共通）

### 0-1. 必要なもの

| 種別 | 要件 | 確認コマンド |
|---|---|---|
| **Node.js** | v20 以上（v22 推奨） | `node -v` |
| **pnpm** | リポジトリ同梱の corepack で有効化（個別インストール不要） | `corepack --version` |
| **Git** | リポジトリ取得・バージョン管理に使用 | `git --version` |
| **ブラウザ** | **Chrome または Edge**（必須） | — |

> ⚠️ **ブラウザは Chrome / Edge を使ってください。** プロジェクトフォルダの読み書きに
> **File System Access API** を使うため、Firefox / Safari ではフォルダを直接開けません（警告が出ます）。

### 0-2. リポジトリを取得して起動する（Windows / PowerShell）

操作は **Windows の PowerShell** を想定して説明します（macOS / Linux のターミナルでも、同じコマンドがそのまま動きます）。

**PowerShell の開き方**: スタートボタンを**右クリック → 「ターミナル」**（または「Windows PowerShell」）。
もしくはスタートメニューで `PowerShell` と検索して起動。黒い（または青い）コマンド入力ウィンドウが開きます。

そのウィンドウに、下のコマンドを **1 行ずつ貼り付けて Enter** で実行します。
（Windows PowerShell 5.1 は `&&` での連結に未対応なので、複数行をまとめず 1 つずつ実行してください。）

```powershell
# 1) 保存したい場所へ移動してから取得（例: ドキュメント直下）
cd ~\Documents
git clone https://github.com/Actoratect/scenario-studio.git
cd scenario-studio

# 2) pnpm を有効化（Node 同梱の corepack を使う。初回のみ）
corepack enable

# 3) 依存をインストール
pnpm install

# 4) 開発サーバを起動（止めるときは Ctrl+C）
pnpm -F frontend dev
#   → http://localhost:5173/ が表示される
```

> **「このシステムではスクリプトの実行が無効になっている…」と出たら**:
> PowerShell の既定で `.ps1`（`pnpm` の実体など）の実行が止められています。一度だけ
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を実行してから上をやり直してください
> （現在のユーザーだけ・ローカル/署名付きスクリプトのみ許可する安全寄りの設定。**`Unrestricted` にはしない**こと）。
>
> **`pnpm` が見つからない場合**: `corepack pnpm install` / `corepack pnpm -F frontend dev`、
> もしくは `npm install` → `npm run dev`（内部で同じ Vite が起動）でも代用できます。
>
> ポート 5173 が使用中なら Vite が自動で別ポートを選びます。起動ログの `Local:` の URL を見てください。
> 2 回目以降は **`pnpm -F frontend dev` だけ**で起動できます（1〜3 は初回のみ）。

### 0-3. ブラウザで開く

**Chrome / Edge** で **http://localhost:5173/** を開くと、Welcome 画面（プロジェクトピッカー）が出ます。

```
┌──────────────────────────────────────────┐
│ Scenario Studio                          │
│  [ 新規プロジェクト ]  空フォルダから作成     │  ← ルート A
│  [ 既存プロジェクトを開く ]  フォルダを選んで開く │  ← ルート B / 既存
│  [ 最近開いた ]  …                        │
└──────────────────────────────────────────┘
```

> **まず触ってみたい人へ**: リポジトリの `sample-projects/meros/`（走れメロスの完成サンプル）を
> **リポジトリの外**にコピーし、「既存プロジェクトを開く」でそのフォルダを選ぶと、実データの構造を体感できます。
> （リポジトリ内のまま開くと編集が Git 差分に出るため、必ず外にコピーしてから開いてください。）

ここから **ルート A** か **ルート B** に進みます。

## ルート A. ゼロから新規プロジェクトを立ち上げる

### A-1. プロジェクトを作る

1. Welcome 画面で **プロジェクト名** を入力（後で変更可）。
2. **「フォルダを選んで新規作成」** をクリック。
3. OS のフォルダ選択ダイアログで、**空のフォルダ**を新規作成して選ぶ
   （例: `~/Documents/ScenarioProjects/my-story/`）。
4. ブラウザが**フォルダへの読み書き許可**を尋ねるので「許可」。

→ 選んだフォルダに `ProjectSettings.yaml` と標準フォルダ一式（`Scenarios/` `Nodes/` `Eras/` `Glossary/` `Relations/` `Media/` …）が作られ、エディタが開きます。

### A-2. 画面の全体像

Workspace は複数パネルのドッキング構成です（ドラッグでフロート/分割、ヘッダ右の **⟳** で初期化）。最初に使うのは主に:

| パネル | 役割 |
|---|---|
| 📚 **アウトライン** | 章・シーンの追加と並べ替え、登場要素（キャラ等）の一覧 |
| 📝 **インスペクタ** | 選択したノード（キャラ/場所/アイテム）のフィールド編集 |
| 🎬 **脚本** | シーンの台本をブロック単位で執筆 |
| 🕸 **グラフ** | キャラ間の関係性を図で編集 |
| 📖 **あらすじ** | 作品全体の Markdown あらすじ |

詳細なパネル早見表は [UserGuide.md §3](./UserGuide.md)。

### A-3. 章とシーンを作る（アウトライン）

1. 📚 **アウトライン** の「シナリオ全体構造」で、下部の入力欄に章名 → **「+ チャプター」**。
2. 章の行の **「+ シーン」** でシーンを追加。
3. 名前を変えたいときは、章・シーン行の **✎ ボタン**でリネーム（タイトルと slug を変更）。
4. 章やシーンは**ドラッグで並べ替え**、シーンは別の章へドラッグで移動できます。

### A-4. 登場人物・場所・アイテムなどを作る

1. アウトライン下部の「要素」セクションで、種別（キャラ/場所/物品/組織/出来事）を選び、名前を入れて **「+ 追加」**。
2. 作ったノードをクリック → 📝 **インスペクタ**で各フィールド（読み仮名・性格・所属など）を編集。
3. キャラのサムネは、画像ファイルをノードへ**ドラッグ&ドロップ**で設定できます。

> キャラの `dev_name`（英字の内部名）は、脚本のセリフで話者を指す ID になります。必ず英字で入れてください。

### A-5. 脚本を書く（スクリプト）

1. アウトラインのシーン行の **「脚本」** ボタン、または 🎬 **脚本**パネルでシーンを選択。
2. 上部ツールバーからブロックを挿入して書きます。ブロック種別:

   | 種別 | 用途 |
   |---|---|
   | `stage` | ト書き・情景描写 |
   | `line` | キャラのセリフ（話者 + 感情タグ） |
   | `aside` | 独白・モノローグ・地の文 |
   | `sfx` / `bgm` | 効果音・BGM の指定 |
   | `choice` | 選択肢分岐 |

3. 書きながら `Tab` で AI の 1 行続き提案を確定（AI 設定後）。

### A-6. 関係性・あらすじ・用語集

- 🕸 **グラフ**: ノード間を `Shift+ドラッグ`で関係を作成。関係は **「A→B 方向のテキスト1本」**で、
  双方向にしたいときは作成時に逆方向のテキストも入れると 2 本（両矢印）になります。線をクリックで編集・削除。
- 📖 **あらすじ**: 作品全体のあらすじを Markdown で記述（画像も埋め込み可）。
- 📘 **用語集**: 正式表記・別表記・禁止表記を登録（表記ゆれを後で一括検出・修正できます）。

### A-7. 保存とバックアップ

- 編集は**自動保存**されます（ヘッダの SaveBadge で状態確認、`Ctrl/Cmd+S` で即時 flush）。
- データは全て**そのフォルダ内のテキストファイル（YAML/Markdown）**。**Git でのバージョン管理を強く推奨**します。
- `.editor/`（machine-local な設定・APIキー暗号化ファイル）は **`.gitignore` に入れて**ください。

### A-8. 書き出し（レビュー / ゲーム連携）

- `Ctrl/Cmd+E` → Export。**レビュー用 1 枚 HTML**（オフラインで開ける・サムネ埋め込み）はレビュアーへの第一手に最適。
- Markdown / プレーンテキスト書き出しも可能。詳細は [UserGuide.md §6](./UserGuide.md)。

## ルート B. 既存ドキュメントを AI で再構築する

すでに **企画書・プロット・キャラ設定・台本テキスト・立ち絵/画像** などがある場合、
それらを AI コーディングツールに読ませて、まとめて ScenarioStudio 形式（YAML/Markdown）へ変換できます。

### B-0. 向いているケース

- Word / テキスト / Markdown の台本やプロットがある
- キャラ設定表・用語集・年表などが別ファイルで散在している
- 立ち絵 / SD / 背景などの画像素材がある

### B-1. 元資料を 1 フォルダに集める

変換先プロジェクト内に `_Ref/`（参照原本）フォルダを作り、元資料をすべて入れます。

```
my-story/
├── _Ref/                     ← 原本（変換元）。ここは触らない
│   ├── 企画書.docx
│   ├── プロット.md
│   ├── キャラ設定.txt
│   ├── 台本_第1話.txt
│   └── 立ち絵/ …
└── （以下、変換で ScenarioStudio 形式が作られる）
```

### B-2. 変換先プロジェクトを用意する

- 空フォルダ（ルート A の A-1 で作ったもの）でも、`sample-projects/_template/` をコピーしたものでも OK。
- `_Ref/` はその中に置きます（原本は**読むだけ**で、変換は別フォルダに出力）。

### B-3. AI コーディングツールを用意する

リポジトリ内の YAML/Markdown を直接読み書きできる AI を使います（ベンダー自由）:

- **Claude Code** / **Cursor** / **Codex** / **Aider** など（手元の端末で動かす CLI / エディタ統合型）
- 完全オフラインにしたい場合は **Ollama などのローカル LLM** を使う構成

> ⚠️ **データの送り先に注意**: Claude Code / Cursor / Codex などは「手元で動く」ツールですが、
> 推論自体は各社の**クラウド LLM（Anthropic / OpenAI など）へ内容を送って**行います
> （＝変換対象のテキストが提供元に送信される）。**端末内で完結させたいなら Ollama 等のローカルモデル**を使ってください。
> 機密素材を扱うなら **B-7** を必ず確認。

### B-4. AI に「変換仕様」を渡す

AI が正しい形式で出力できるよう、**次の 2 つを必ず読ませて**ください:

1. [`Documentation/UserGuide.md`](./UserGuide.md) の **§8「AI 向け — フォルダ構造 / データ作成スペック」**
   （ディレクトリ構成・各ファイルのスキーマ・script ブロック種別・ID 規則・やってはいけないこと、まで網羅）
2. **完成サンプル** `sample-projects/meros/`（走れメロス）— 「形をコピーすれば 8 割正解」の手本

### B-5. 変換を依頼する（プロンプト例）

```
`Documentation/UserGuide.md` の §8 と `sample-projects/meros/` を読んで、
ScenarioStudio のデータ形式を把握して。

そのうえで、このプロジェクトの `_Ref/` にある資料を ScenarioStudio 形式へ変換して。
- 登場人物・場所・アイテム・組織 → Nodes/ 配下のノード
- 台本テキスト → Scenarios/<章>/<シーン>.scn.yaml（地の文=aside、セリフ=line、ト書き=stage…）
- 用語 → Glossary/terms.yaml、関係 → Relations/relations.yaml
- 画像 → Media/ に配置し、キャラの thumbnail に紐付け

原文のセリフ・ト書きは要約せず一字一句保持して。判断に迷う箇所はコメントで残して。
作り終わったら、参照切れ・重複 ID・必須フィールド欠落がないか自己チェックして。
```

> 大量のシーンがある場合は「1 シーンずつ確実に」と区切ると精度が上がります。

### B-6. 変換結果を検証する

1. エディタで**そのフォルダを開く**（「既存プロジェクトを開く」）。
2. 🩺 **Project Health** / ⚠ **コンソール（Lint）** で
   `node-ref-missing`（参照切れ）・`missing-display-name`・`script-unknown-who`・`empty-script` などを確認。
3. 🗺 **Plot Flow Lens** で選択肢（choice）の遷移先が実在するかを可視化。
4. 機械チェック（任意）: リポジトリで `pnpm test` 等。YAML の構文・参照整合は `yaml` パーサでも確認可能。

### B-7. 🔒 機密・未公開プロジェクトの扱い（重要）

未公開企画など外に出せない素材を AI で扱う場合は、**「データがどこへ送られるか」を必ず意識**してください。

- **AI の送り先を理解する**: クラウド AI（Claude / OpenAI / Gemini 等。**Claude Code / Cursor / Codex も裏でこれらに送る**）を使うと、
  変換対象のテキストが提供元に渡ります。**端末から一切出したくないなら Ollama 等のローカル LLM** か、オフライン構成にする。
- 使う AI に **「外部 / ネットワーク / Web 検索 / クラウドストレージ系のツールは使わず、ローカルファイルのみ」** と明示する
  （サブエージェントを使う場合も同様に徹底）。クラウド同期・Web 検索・外部アップロードを挟まない。
- 変換先フォルダを**社外リポジトリへ push しない**。Git 管理するならプライベート / ローカル限定に。
- 提供元に送ってよいかは、**自分の契約・規約・社内ルールで判断**する（学習利用の有無・保存期間などはプロバイダにより異なる）。

### B-8. 取り込み後の微修正

- 章・シーン名は アウトライン / 脚本ヘッダの **✎** でリネーム。
- フィールドの追記・修正は 📝 インスペクタ。
- 用語の表記ゆれは `Ctrl/Cmd+Shift+Q` のスキャンで一括修正候補を確認。
- 以降の「書く・直す・整える」の流れは [UserGuide.md §4](./UserGuide.md) を参照。

## セキュリティ上の注意（A / B 共通）

ローカルファースト設計のため外部送信は最小限ですが、**「ローカルに置く」だけでは AI への送信は防げません**。
次の点を理解しておいてください。

| 項目 | 何が起きるか | 対策 |
|---|---|---|
| **AI にデータが渡る** | クラウド AI（Claude / OpenAI / Gemini、および Claude Code / Cursor / Codex）は、補完・要約・変換のため**送ったテキストを提供元へ送信**する | 機密は B-7。端末内で完結させたいなら Ollama 等のローカル LLM。送信前に **Show prompt** で内容確認 |
| **`pnpm install` が依存のスクリプトを実行** | install は依存パッケージのビルド / postinstall で**任意コードが走り得る**（サプライチェーン） | **信頼できる取得元**のみ。lockfile を固定（CI は `--frozen-lockfile`）。不審な依存追加に注意 |
| **フォルダへの読み書き許可** | File System Access API で、**許可したフォルダ配下を読み書き**できる | 許可は**プロジェクトフォルダだけ**に。ホーム直下やシステム領域を選ばない |
| **API キーの保存** | AI プロバイダのキーは `.editor/ai-keys.json` に **暗号化（WebCrypto / PBKDF2）** して保存 | `.editor/` は **`.gitignore`** に入れる。コミット・共有しない |
| **書き出し物に内容が入る** | レビュー用 HTML は画像まで埋め込んだ**自己完結ファイル**。AI ハンドオフ（`Cmd/Ctrl+Shift+H`）も本文を含む | 機密プロジェクトの Export / ハンドオフ物の**共有先に注意**。外部 AI へ貼る内容も同じ |
| **dev サーバの公開範囲** | `pnpm dev` は **localhost のみ**で待受（`--host` を付けない限り LAN には出ない） | 共有 PC / 公共ネットワークでは `--host` を付けない |
| **PowerShell 実行ポリシー** | `RemoteSigned` はローカル/署名付きのみ許可する安全寄り設定 | `Unrestricted`（無制限）にはしない。`-Scope CurrentUser` で最小範囲に |

> まとめ: 守るべきは主に **① AI への送信先 ② 依存の取得元 ③ 書き出し/共有物** の 3 点です。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `pnpm` が見つからない | `corepack enable` を実行。だめなら `corepack pnpm …` か `npm install` / `npm run dev` で代用 |
| フォルダを開く画面が出ない / 警告が出る | **Chrome / Edge** で開いているか確認（File System Access API 必須） |
| 起動したのに変更が反映されない | ブラウザを**ハードリロード**（`Ctrl+Shift+R`）。dev サーバ再起動も有効 |
| 保存できない（SaveBadge が赤） | 外部で同じファイルを編集して競合した可能性。Toast を確認し、必要ならリロードで取り込み |
| 文字化け | YAML/Markdown は **UTF-8（BOM なし）** で保存。外部エディタの保存設定を確認 |
| レイアウトが崩れた | ヘッダの **⟳** で初期化 |

より詳しい「ハマりどころ」は [UserGuide.md §9](./UserGuide.md)。
